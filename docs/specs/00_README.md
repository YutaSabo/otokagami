# Otokagami 仕様書体系

> 文書状態: 現役
> 上位正本: [マスター設計書](../../マスター設計書.md)

このディレクトリは、新しいOtokagami MVPの製品・UX・学習・技術仕様を定義する。コードやDBの現状は仕様への適合を意味しない。旧設計による実装は、明示的に「現在実装」「移行対象」と記述した箇所だけを事実として参照する。

## 権威と優先順位

1. `AGENTS.md`と`.ai`設定: 作業・安全・Git・外部操作の規則
2. `マスター設計書.md`: 製品全体の最上位方針
3. この文書: 仕様書の責務、用語、読む順番
4. `01`〜`10`: 分野別の現役仕様
5. Phase 13以降: 現役仕様を検証するための受け入れ文書
6. Phase 01〜12: 方向転換前の完了済み履歴。現在仕様ではない

矛盾した場合は上位文書を優先し、下位文書を修正する。実装が異なる場合、実装を無条件に正当化せず差分として扱う。

## 全文書で固定する決定

| 項目 | 決定 |
| --- | --- |
| 正式名称 | Otokagami |
| 対象 | 国籍・母語を問わない英語学習者 |
| 初期市場 / UI | 日本 / `ja-JP` |
| 初期判定 | Azure `en-US` |
| 判定入力 | アプリ管理課題のみ |
| 日次 | 1焦点音、通常5課題、良好日は3課題程度、任意追加2課題 |
| coached retry | 原則1課題、1課題最大3有効attempt |
| durable進捗 | 各日・役割の最初の有効な無補助attempt |
| 復習 | 1・3・7・14日 |
| 無料体験 | 最初の有効判定から7 active learning days、非自動課金 |
| 課金開始 | Day 7レポート後、8回目の学習日前 |
| コンテンツ | 初期8焦点群、約104課題、約208音声 |
| ユーザー音声 | 自社保存なし。代表before/afterのみ端末で最大30暦日 |
| 価格 | 月額・年額構造。商品と実価格はTBD |
| 完成範囲 | App Store申請・一般公開を含まない |

## 用語

| 用語 | 定義 |
| --- | --- |
| 焦点音 | その日の改善対象となる1つの音または音群 |
| 管理課題 | 文面、IPA、焦点位置、音声、助言、版が事前に確定・レビューされた課題 |
| Program Day | 完了した有効学習日の順序。無料体験ではDay 1〜Day 7 |
| Calendar Date | ユーザーのタイムゾーンによる実日付 |
| Review Due Date | 1・3・7・14日復習が期限となる実日付 |
| attempt | 録音開始ではなく、1回の判定試行を表す記録単位 |
| 有効attempt | 音声品質、課題一致、Azure結果、必要項目が検証できたattempt |
| 無補助attempt | 当該判定前にコーチを提示していないattempt |
| guided retry | コーチ提示後、同じ課題を再録音したattempt |
| durable進捗 | 日をまたいだ維持・転移・定着に使える学習証拠 |
| correction cycle | before、提示助言、afterを結ぶ即時改善の組 |
| 主要結果 | 対象1音の状態と次の行動。長期集計を待たず表示する |

## 未確定値の表記

- `確定`: 採用済みの製品・安全条件
- `MVP初期値`: 実装開始用だが、実機データで調整する値
- `実機検証目標`: まだ合格実績のない速度・成功率候補
- `仮説`: ユーザー行動や収益で検証する値
- `TBD`: 決定材料が足りない
- `未確認`: 外部状態または実機状態を確認できていない

しきい値、価格、成功率を根拠なく`確定`へ昇格させない。

## 現在実装との関係

現在のworkspace、パッケージ、アプリ表示、API識別子には旧称`Pronunciation Mirror`が残る。自由入力、詳細スコア、実行時OpenAI/Piper/Python等もコード上は残っている。第3段階では名称・コード・DB・外部環境を変更せず、これらを第4段階以降の移行対象とする。
