# Otokagami UX仕様

> 文書状態: 現役
> 対象: iPhone MVPの画面・状態・遷移

## 1. UX原則

1. 最初に見せるのは、対象1音の状態と次に試す1行動だけ。
2. 録音停止後、長期保存や集計を待たず主要結果を表示する。
3. 1問の標準導線は、画面遷移を増やさず同じ文脈で再挑戦できるようにする。
4. 総合点や詳細指標を主役にしない。
5. 技術失敗を悪い発音として表示しない。
6. 中断・休止・復帰を罰しない。

## 2. 必要な画面領域

ナビゲーションの最終的なタブ数はTBDだが、MVPには次の領域が必要である。

| 領域 | 役割 |
| --- | --- |
| オンボーディング | 製品の約束、マイク、Azure送信、無料体験を説明 |
| ホーム | 今日のProgram Day、焦点音、続き/開始、期限復習を表示 |
| 日次セッション | 5課題とguided retryを1問ずつ進める |
| 日次まとめ | 今日得た証拠と次回予定を示す |
| 進捗・レポート | 改善・維持・転移・定着と今後の計画を示す |
| 課金ウォール | Day 8前に継続計画と月額/年額を提示 |
| 設定 | 購入復元、通知、書き出し、削除、規約 |

現在実装の4タブ、自由入力、音素選択、別建て苦手ドリル、3画面詳細フローは目標UXではない。第3段階ではコードを変更せず、移行対象として記録する。

## 3. 初回起動とオンボーディング

### 説明すること

- 1日1つの焦点音を扱う。
- 判定はアプリが用意した英語課題だけに行う。
- 初期判定はAzure `en-US`であり、人間評価そのものではない。
- ユーザー音声は端末からAzureへ送るが、自社サーバーやSupabase Storageには保存しない。
- 代表before／afterだけ端末へ最大30暦日保持できる。
- 無料体験は7回の有効な学習日で、自動課金されない。
- Day 7後、次の新規判定前に購入案内が出る。

### 初期化

- Supabase anonymous authを使い、メール登録を必須にしない。
- `coaching_locale=ja-JP`、`assessment_locale=en-US`を初期値とする。
- タイムゾーンを取得し、Calendar Dateの根拠にする。
- アプリ起動や匿名認証作成だけでは無料Program Dayを開始しない。
- 通知許可は価値を説明できるタイミングで依頼する。

## 4. ホーム

### 未開始

- `Program Day N`または課金後の今日の計画。
- 今日の焦点音候補または「まず1音を見つける」。
- 大きな開始ボタン。
- 期限超過復習があれば「復習1件を含みます」と穏やかに示す。

### 進行中

- 焦点音。
- 必須課題の進捗`n / 5`、または短縮が確定した場合の`n / 3`。
- 「続きから」ボタン。
- 任意追加2課題を必須進捗に混ぜない。

### 完了

- 今日の成果を「改善」「維持」「転移」「発見」のいずれかで表示。
- 次のReview Due Date。
- 任意追加2課題への控えめな導線。
- ストリーク喪失を主役にしない。

### 無料体験終了

Day 7レポートと過去結果は表示できる。新しい判定へ進む操作で課金ウォールを表示する。

## 5. 1問の標準体験

### 5.1 録音前

表示するもの:

- 課題文
- 今日の焦点音と対象箇所の強調
- 標準音声、スロー音声
- 録音ボタン
- 課題番号と役割を簡潔に示す補助情報

IPAは補助表示に置き、最初から全音素を大きく表示しない。

### 5.2 準備・録音中

録音状態は少なくとも次を区別する。

```text
idle → preparing → ready → recording → finalizing → assessing
                           ↘ cancelled / technical_failure
```

- 問題表示中に短期トークンとRecognizerを先読みする。
- 録音ボタンから実際の録音開始まで反応を止めない。
- 録音中は経過時間、停止、簡単な入力反応だけを表示する。
- スコア、推定音、内部処理名は表示しない。
- 画面離脱時は録音破棄を確認する。

### 5.3 判定待ち

- 300〜500msを超える見込みなら待機表示を出す。これはUX設計値であり、性能達成実績ではない。
- 「`/r/`を確認しています」のように対象1音を示す。
- DB保存や長期集計の進行は見せない。
- UX上の打ち切り候補は8秒だが、`実機検証目標`であり、正式値はTBD。

### 5.4 最初の結果

改善が必要な例:

```text
right の /r/

今回の判定では、
/l/ に近く認識されました。

次は、舌先を上あごにつけないことを試します。

[コツを試す]
```

良好な例:

```text
right の /r/

今回の判定では、
目標の音に近く発音できています。

[次へ]
```

主要結果に表示しないもの:

- 総合Pronunciation Score
- 全音素IPA
- Fluency、Completeness、Prosody
- 全候補音素、Azure生JSON

補助的な数値を置く場合も、対象音に限定し、改善状態より目立たせない。

### 5.5 コーチ

- 一度に1つの動作。
- 1〜2文。
- レビュー済み図解1枚。
- 標準/スロー音声。
- CTAは「このコツで、もう一度」。
- 主コツで変化しない場合だけ代替コツへ進む。
- 実行時生成を待たない。

### 5.6 guided retry

- コーチ後の標準再録音は1回。
- 希望時のみさらに1回できる。
- 1課題最大3有効attempt。
- 技術的に無効な録音は上限に含めない。
- guided retryは即時改善の証拠で、維持・転移・定着へ直接加算しない。

### 5.7 before／after

```text
/r/ の変化

最初: 調整が必要
今回: 目標の音に近づきました

[最初を聞く] [今回を聞く]
[次へ]
```

- 「定着」「習得」とは表示しない。
- 音声ファイルが欠損していれば再生ボタンだけを無効にし、状態・日付・説明は表示する。
- 保存再試行中でも主要結果と次への操作を妨げない。

### 5.8 次へ

- 次の問題と音声を先読みする。
- 現在の課題を二重完了させない。
- 保存に失敗しても録音をやり直させず、結果を端末の再送待ちとして扱う。

## 6. 日次セッション

### 通常5課題

1. アンカー単語
2. 対照課題
3. 別単語への転移
4. 短文または実用文
5. 過去音の復習

### 良好日の短縮

アンカーと別の役割で焦点音が良好な場合、3課題程度で「維持できています」と完了できる。別の焦点音へ切り替えない。

### 任意追加

必須課題完了後に最大2課題を提示できる。スキップしてもProgram Day、レポート、購読アクセスへ不利益を与えない。

## 7. 中断・再開

- 完了済み課題、現在位置、焦点音、correction cycleを保存する。
- 録音途中・判定途中は再開せず、その課題を録音前から再開する。
- 未完了セッションはCalendar Dateが変わっても同じProgram Dayで続ける。
- 新しいCalendar Dateでは、Review Due Dateを再評価し、必要なら未開始の復習枠へ最大1件反映する。
- 再開によって同一client attemptを二重保存しない。
- 1 Calendar Dateで2つのProgram Dayを完了させない。

## 8. 最初の7 active learning days

これは連続暦日ではなく、完了した有効学習日の順序である。

| Program Day | 体験 |
| ---: | --- |
| 1 | 初期スクリーニング、焦点音1、最初のコーチとbefore／after |
| 2 | 焦点音1の無補助維持、対照または短文 |
| 3 | 焦点音1の別語・別文への転移 |
| 4 | 焦点音2の発見・即時変化、焦点音1の期限復習があれば1件 |
| 5 | 焦点音2の維持、必要な過去音復習 |
| 6 | 焦点音2の転移、焦点音1の実用文確認 |
| 7 | 7日相当の実日付証拠があれば反映し、7日レポートと次の14日計画 |

Program Dayの進行が休止された場合、Review Due Dateとの関係によりDay 7時点で7日復習がまだ到来していないことがある。その場合は「定着確認中」と正直に表示し、達成済みにしない。

## 9. Day 7レポートと課金ウォール

### レポート

- その場で変化した焦点音
- 後日も維持できた焦点音
- 別語・別文へ転移できた焦点音
- 定着確認中の焦点音
- 次の14日計画
- 端末に残る代表before／after

### 課金ウォール

- Day 7レポート後、8回目の有効学習日となる新規判定前に表示。
- 月額・年額を提示するが、実価格と商品情報はRevenueCatから取得し、設計書で固定しない。
- 自動課金の無料トライアルと誤認させない。
- 閉じた場合も過去レポート、選択録音、設定、復元、書き出し・削除、規約を閲覧できる。

## 10. 課金後のUX

- 週次に、即時改善・維持・転移・定着確認中・次の焦点を示す。
- 期限復習と新規焦点を同じ日次計画へ統合する。
- 休止後は「前回の続き」と期限超過復習1件を提示する。
- 同じ音で停滞したら代替コツ、易しい課題、後日再訪を選ぶ。
- レベル、バッジ、称号、総合点グラフで継続を代替しない。

## 11. エラーUX

| 状況 | 表示・動作 |
| --- | --- |
| 無音・短すぎ・クリッピング | 「音声を十分に確認できませんでした」。成果とattempt上限へ含めない |
| 違う課題・対象音欠損 | 発音の良否を出さず再試行。連続失敗時は代替課題 |
| Azure NoMatch/取消/タイムアウト | 再試行。Program Day・進捗へ影響させない |
| 保存失敗 | 主要結果は表示し、再送待ちを非妨害的に示す。再録音させない |
| 購読確認失敗 | 過去閲覧を維持し、新規判定前に再確認する |
| 音声URI欠損 | 再生だけを無効化し、画面全体を壊さない |
| オフライン | 新規Azure判定不可。保存済みレポート・設定は閲覧可 |

## 12. アクセシビリティ

- 色だけで状態を表さず、文言・記号を併用する。
- IPAだけで行動を説明しない。
- 録音、停止、再生、次へ、購入、削除に十分なタップ領域を確保する。
- Dynamic Type、VoiceOver、Reduce Motionを考慮する。
- 録音中・判定中・失敗を音以外でも認識できるようにする。

## 13. 性能値の扱い

主要結果P95 3秒、初回録音可能P95 1.5秒、2問目以降0.5秒、異常時8秒等は`実機検証目標`であり、達成済みの合格基準ではない。正式な受け入れ値は実機データから決定する。
