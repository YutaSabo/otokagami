# Otokagami MVP範囲

> 文書状態: 現役
> 対象: iPhone向けMVPの機能境界

## 1. MVPの目的

MVPは、管理課題を用いて毎日1つの焦点音を発見し、短い静的コーチと再録音で即時変化を示し、1・3・7・14日復習と別課題で定着を確認できるところまでを成立させる。

## 2. 中心体験に必須

| 機能 | 必要な理由 |
| --- | --- |
| 最小オンボーディング | 製品の約束、音声送信、無料体験を誤解なく始めるため |
| 初回スクリーニング | 複数候補から、その日に扱う焦点音を1つ選ぶため |
| 1日1焦点音プランナー | 次の行動を迷わせないため |
| 通常5課題 | アンカー、対照、転移、文、復習を短時間で扱うため |
| 良好日の短縮 | 弱点を無理に作らず、3課題程度で完了させるため |
| 任意追加2課題 | 完了条件を重くせず、希望者だけ練習量を増やすため |
| Azure直接判定 | 管理課題を音素単位で評価するMVP唯一の判定基盤だから |
| 対象1音の主要結果 | 次に直す場所と行動をすぐ理解させるため |
| 静的コーチ・図解 | 内容と表示速度を安定させるため |
| coached retry | その場の変化を作るため |
| before／after比較 | 即時変化を点数だけでなく状態と音声で示すため |
| 学習状態 | 即時改善と定着を混同しないため |
| 1・3・7・14日復習 | 後日の無補助再現を確認するため |
| 日次・Day 7・週次レポート | 継続する改善計画を見せるため |

### 日次の固定仕様

- 1日1焦点音。
- 通常5課題。
- 焦点音が良好なら3課題程度で短縮完了。
- 完了後の追加2課題は任意で、完了条件に含めない。
- 5課題はアンカー単語、対照課題、別単語、短文または実用文、過去音の復習。
- コーチ付き再録音は原則1課題。
- 1課題につき最大3回の有効attempt。
- 技術的に無効な録音はattempt数・成果・Program Dayへ含めない。

## 3. 体験品質を守るために必須

| 機能 | 必要な理由 |
| --- | --- |
| 問題・音声・助言の先読み | 録音開始とコーチ表示を待たせないため |
| 録音品質ゲート | 無音、短すぎ、クリッピング等を発音結果にしないため |
| 課題一致・必須結果検証 | 違う語や不完全なAzure結果を学習証拠にしないため |
| 単一の録音状態管理 | 連打、古い応答、画面破棄後の結果混入を防ぐため |
| 中断・再開 | 未完了Program Dayと現在位置を保持するため |
| 代替課題・スキップ | 技術失敗でセッション全体を止めないため |
| 主要結果と保存の分離 | DB・集計処理でフィードバックを遅らせないため |
| idempotency | 再送によるattempt・進捗の重複を防ぐため |
| 保存再試行 | 保存失敗時に録音をやり直させないため |
| 速度・失敗・原価計測 | 品質目標を実機データで調整するため |

## 4. 課金・信頼・運用に必須

| 機能 | 必要な理由 |
| --- | --- |
| Supabase anonymous auth | 登録負担を減らしながら継続状態を識別するため |
| 7 active learning days | 価値を7回の有効学習で体験してもらうため |
| RevenueCat + iOS IAP | 月額・年額購読、復元、entitlementを管理するため |
| Day 8前の課金ウォール | 無料計画から有料計画へ明確に切り替えるため |
| 過去結果の無料閲覧 | 購入しない利用者のデータ権利と信頼を守るため |
| コンテンツレビュー状態 | 未確認課題を判定に出さないため |
| データ書き出し・削除 | 利用者が学習データを管理できるため |
| 秘密情報・RLS・サーバー権限 | protected dataと進捗をクライアントだけに任せないため |
| ログ・監視 | Azure、保存、課金障害を識別するため |

## 5. 7 active learning days

- アプリ管理。Apple Introductory Offerなし。自動課金なし。
- 最初の有効な学習判定から開始。
- Program Dayは有効セッション完了時だけ進む。
- 1 Calendar Dateにつき最大1 Program Day。
- 休み、起動だけ、未完了では進まない。
- 未完了は同じDay・同じ位置から再開。
- Review Due Dateは実日付で進み、期限超過は次回に最大1件提示。
- Day 7完了後にレポートを表示し、8回目の学習日前に購入を案内。
- 非購入でも過去レポート、改善状態、選択録音、設定、復元、書き出し・削除、規約を閲覧可能。

## 6. コンテンツ最低量

- 初期8焦点群 × 12課題 = 96課題。
- 初回診断候補8課題。
- 合計約104課題。
- 標準・スロー音声約208ファイル。
- 主・代替コツ16件、汎用コツ5件、助言最低21件。
- 正式図解最低8件。
- すべて発音指導者レビューとAzure実機検証を経て有効化する。

## 7. MVPから完全に外す

- 自由入力
- レベル、バッジ
- App Store申請・一般公開

コードやDBが現在存在しても、MVPの利用可能機能とはみなさない。

## 8. UIから無効化する移行対象

第4段階以降、削除可否を判断するまで入口を閉じる対象である。第3段階ではコードを変更しない。

- 音素表からの手動練習
- 別建ての苦手ドリル
- 日・週・月の総合点グラフ
- 全41音ヒートマップ
- 長期録音履歴
- 旧詳細スコアを中心にした導線

## 9. 将来候補として残す

## 12. 技術境界

- AzureだけをMVP判定に使う。
- ユーザー音声を自社サーバー、DB、Supabase Storageへ保存しない。
- 管理課題のIPA、標準/スロー音声、助言、図解は事前生成・レビューする。
- 実行時OpenAI/Piper/Pythonを中心経路から外す。
- 主要結果は保存・長期集計を待たず表示する。
- durable進捗は信頼できるサーバーまたはデータポリシー境界で確定する。

## 13. MVP完成条件

- 通常5課題、短縮、任意追加の中心体験が一貫して動く。
- 対象1音の結果、コーチ、再録音、before／afterが短い待ち時間で動く。
- guided retryとdurable進捗が分離される。
- Program Day、Calendar Date、Review Due Dateが正しく扱われる。
- 7 active learning daysとDay 8前課金ウォールが動く。
- 1・3・7・14日復習と期限超過復帰が動く。
- 約104課題と必要アセットがレビュー済みで有効化される。
- 保存再送が重複せず、保存失敗で録音をやり直させない。
- 音声、秘密、データ削除、購読の境界を検証できる。
- 自動テストと必要な実機確認を通過する。

App Store申請、TestFlight一般配布、Productionデプロイは完成条件に含めない。
