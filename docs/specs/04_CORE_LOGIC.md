# Otokagami 学習ロジック

> 文書状態: 現役
> 数値しきい値: 特記がない限りTBD

## 1. 不変原則

1. 1つの有効学習セッションは1焦点音だけを扱う。
2. guided retryは即時改善だけを示し、durable進捗を増やさない。
3. durable進捗には、各Calendar Date・焦点・課題役割の最初の有効な無補助attemptを使う。
4. 技術的に無効な録音をattempt上限、状態、復習、Program Dayへ含めない。
5. 保存再送や同日再録音で進捗を重複加算しない。
6. しきい値未確定時に「合格」「定着」を推測しない。

## 2. 日付モデル

### Program Day

ユーザーが有効な日次セッションを完了した順序である。無料体験はDay 1〜Day 7。

- アプリ起動、匿名認証、最初の画面表示だけでは進まない。
- 有効な学習判定が一つもなければ開始しない。
- 必須課題を完了した時だけ完了する。
- 1 Calendar Dateにつき最大1 Program Dayを完了できる。
- 未完了なら後日も同じ番号を継続する。

### Calendar Date

ユーザーのIANA timezoneによる実日付。attemptの証拠日、1日上限、音声保持期限に使う。タイムゾーン変更時の重複防止はサーバー側の記録で判断し、端末の申告だけでProgram Dayを二重完了させない。

### Review Due Date

焦点音の1・3・7・14日復習が期限となる実日付。起点は対象となる有効な無補助証拠のCalendar Date。

- 休んでも期限は実日付で進む。
- 期限超過を失敗にしない。
- 自動消化しない。
- 次回起動時に日次セッションへ原則1件まで優先挿入する。

## 3. 日次プラン

### 標準5課題

| position | prompt role | 内容 |
| ---: | --- | --- |
| 1 | `anchor` | 焦点音のアンカー単語 |
| 2 | `contrast` | 対照音または対照課題 |
| 3 | `transfer_word` | 別単語への転移 |
| 4 | `sentence` / `practical_sentence` | 短文または実用文 |
| 5 | `review` | 過去焦点音の期限復習 |

同じ課題IDを必須枠内で重複させない。課題不足時に未レビュー課題を有効化してはならない。

### 短縮

アンカーと、異なる課題役割の無補助attemptがともに良好と判断できる場合、必須課題を3件程度へ短縮できる。良好判定のしきい値は`MVP初期値`として別途決め、焦点音別の実機検証で調整する。

### 任意追加

必須完了後に`optional_extension`を最大2件提示できる。

- Program Day完了に不要。
- durable進捗へ使う場合も、その日・役割で既に証拠があれば重複加算しない。
- 拒否や中断を失敗にしない。

## 4. 焦点音の選定

優先順は次の証拠から決める。

1. 初回スクリーニングまたは期限復習で、再現性のある改善候補。
2. Review Due Dateが到来した既存焦点音。
3. 転移・定着に必要な次の文脈。
4. 未評価の有効な焦点群。

国籍・母語を選定重みや判定補正に使わない。発音指導者レビューとAzure実機検証を通過した焦点群だけを選ぶ。

焦点音が良好でも、その日に次の焦点音へ切り替えない。短縮して翌日へ進める。

## 5. attempt

### 役割

| role | 定義 | durable進捗 |
| --- | --- | --- |
| `cold` | 助言前の最初の無補助判定 | 対象 |
| `guided_retry` | コーチ提示後の再録音 | 対象外 |
| `transfer` | 別語・別文の最初の無補助判定 | 対象 |
| `review` | Review Due Dateに行う最初の無補助判定 | 対象 |
| `optional_extension` | 完了後の任意課題 | 重複しない場合のみ候補 |

### 有効条件

有効attemptには少なくとも次が必要である。

- マイク・音声形式が正常。
- 無音、極端な低音量、短すぎ、クリッピングではない。
- 管理課題の参照文と発話が対応する。
- AzureがNoMatch/取消ではない。
- 対象音と必要な判定項目が取得できる。
- そのattemptのclient IDと内容が整合する。

Azure成功後のDB保存失敗は、音声判定を技術的に無効にしない。端末へ判定結果を保持し、同じclient attempt IDで保存を再送する。durable進捗はサーバー確定まで保留する。

### 回数

- 1課題最大3有効attempt。
- 技術的に無効な録音は数えない。
- 同じclient attemptの再送は新しいattemptにしない。
- 連続技術失敗時は代替課題またはスキップを提示する。

## 6. correction cycle

correction cycleは次を結ぶ。

- beforeとなる最初の有効な無補助attempt
- 提示したadvice IDとversion
- afterとなるguided retry
- 対象焦点音
- 変化ラベル
- 端末ローカル音声の有無

guided retryが複数ある場合、ユーザー表示用afterを1件選べるが、選択方法はdurable進捗と切り離す。同日最高点を習熟度へ加算する旧best-attempt方式は、新MVPの規範にしない。

## 7. 学習状態

### 発見 `discovered`

無補助の管理課題で、焦点音に改善候補があると確認された状態。何点未満か、何課題で再現を要求するかはTBD。単一の不完全なAzure応答だけで確定しない。

### その場で改善 `immediate_change`

同一correction cycleのbeforeとguided retryに意味のある変化がある状態。点差、帯の変化、認識音の変化は`MVP初期値`として焦点音別に調整する。同日の証拠だけで維持・定着へ進めない。

### 維持 `held`

別Calendar Dateの最初の有効な無補助attemptで成功した状態。最低経過時間と成功基準はTBD。

### 転移 `transferred`

アンカーとは異なる単語または文の最初の有効な無補助attemptで成功した状態。同じ文の暗記を転移としない。

### 定着 `stable`

複数のCalendar Date、異なる文脈、7日確認を含む証拠がそろった状態。同日の反復だけでは到達しない。正式な証拠数と焦点音別基準はTBD。

### メンテナンス `maintenance`

定着後、14日以降の無補助確認を待つ状態。失敗時に成果を全消去せず、再調整・再復習へ戻す。

## 8. 復習スケジュール

1・3・7・14日の各間隔はCalendar Dateで計算する。

| 間隔 | 主な目的 |
| ---: | --- |
| 1日 | 翌日以降の維持 |
| 3日 | 別語・短文への転移 |
| 7日 | 異なる日と文脈での定着確認 |
| 14日 | メンテナンス |

- 成功時の次段階、不成功時の戻し方は焦点音別しきい値とともに`MVP初期値`として調整する。
- 休止を失敗にしない。
- 期限超過は次回セッションに最大1件。
- 期限超過が複数あれば、古さ、定着への重要度、最近の不安定さで順位付けする。具体重みはTBD。

## 9. durable進捗の重複防止

進捗に採用できる証拠キーは、少なくとも次を一意に識別する。

```text
user + calendar_date + focus_group + prompt_role + evidence_kind
```

- guided retryは`immediate_change`の証拠にだけなる。
- 同日再録音でpractice countや習熟度を増やさない。
- 同じclient attempt IDの再送を重複保存しない。
- クライアントが`durable=true`と申告するだけで確定しない。
- サーバーまたはデータポリシー境界が、課題、日付、役割、既存証拠を検証する。

## 10. Program Day完了

### 通常日

5つの必須slotが、成功または許可された代替/スキップ結果で終わり、有効な学習判定が存在すること。

### 短縮日

短縮条件がサーバー側で確認され、3課題程度の必須slotが完了したこと。

### 完了しないもの

- 画面を開いただけ。
- 録音がすべて技術的に無効。
- 任意追加だけを実行。
- クライアント時刻だけを変更。
- 保存未確定の状態をサーバー確認なしに完了扱い。

完了は冪等に確定し、同じCalendar DateでProgram Dayを二重加算しない。

## 11. 初回7日

Program Dayと実日付を分けるため、Day番号だけで維持・定着を断定しない。

- Day 1: スクリーニング、焦点音1、immediate change候補。
- Day 2: 到来していれば1日維持。到来していなければ別役割の無補助証拠。
- Day 3: 焦点音1の転移。
- Day 4: 焦点音2、焦点音1の期限復習があれば1件。
- Day 5: 焦点音2の維持候補。
- Day 6: 焦点音2の転移、焦点音1の実用文。
- Day 7: 取得済み証拠のレポート。7日Review Due Date未到来なら定着確認中とする。

Day 7完了後、8回目の学習日となる新規判定を始める前に購読を確認する。

## 12. レポート

日次・7日・週次レポートは、平均点や全音素順位ではなく次を集計する。

- 発見した焦点音
- immediate changeを確認したcorrection cycle
- held / transferred / stable / maintenanceの証拠
- 次に到来するReview Due Date
- 次の焦点・課題役割
- 代表before／afterのローカル利用可否

## 13. 未確定値

- 発見に必要な課題数・スコア・認識音条件
- 即時改善の点差・帯・認識音条件
- 維持・転移・定着の最終合格基準
- 短縮判定の具体基準
- 復習失敗時の状態遷移
- 期限超過復習の優先重み

これらを既存の80点や10点へ自動的に固定しない。
